# Project backlog

- [ ] **Multi-platform builds and downloadable GitHub Actions artifacts.** ([#8](https://github.com/Warsinger/math-visualization/issues/8)) **Status: pending.** Extend the existing Windows formatting/lint/test/build CI into a multi-platform build matrix and publish its outputs as downloadable GitHub Actions artifacts. Decide exact operating systems and architectures during implementation; Windows, macOS, and Linux are candidates, not selected commitments. Verify successful builds and artifact naming/contents for every selected target. Release publishing, signing, and installers remain separate undecided scope.

- [ ] **Support the pi constant in equation input.** ([#1](https://github.com/Warsinger/math-visualization/issues/1)) **Status: pending.** Accept both spelled-out `pi` and the Greek symbol `π` as aliases for the same mathematical constant, usable in expressions and function arguments such as `sin(pi/2)` and `cos(π)` with radians. Add parser/evaluation tests for both aliases, their equivalent values, and use within arithmetic and function calls when implementing.

- [ ] **Support Euler's number in equation input.** ([#2](https://github.com/Warsinger/math-visualization/issues/2)) **Status: pending.** Accept `e` as the mathematical constant Euler's number in equations and function arguments such as `ln(e)` and `e^x`. Add parser/evaluation tests for its value and use in expressions, while preserving scientific numeric notation such as `1e-2`. Implement alongside the pending `pi`/`π` constants; no constants are implemented yet.

- [ ] **History of user-entered plots and shapes.** ([#3](https://github.com/Warsinger/math-visualization/issues/3)) **Status: pending.** Let users review and revisit plots and shapes they previously entered. Persistence across sessions, saved parameters/camera state, search, and favorites remain undecided design details, not requirements for this item.

- [ ] **Display the formula for the current curve or shape.** ([#4](https://github.com/Warsinger/math-visualization/issues/4)) Show the mathematical formula for whatever curve or shape is currently displayed, updating it as the displayed object changes. Use readable standard mathematical notation as much as feasible, including properly formatted symbols, fractions, and superscripts where appropriate. **Status: pending.** The existing plain-text helix formula is an initial reference, not completion of this richer notation feature.

- [ ] **Customize axis colors and coordinate-driven curve gradients.** ([#5](https://github.com/Warsinger/math-visualization/issues/5)) Allow a separate color for each X, Y, and Z axis, and display the curve with gradients along each axis using those axis colors. **Status: pending.** Blending, coordinate normalization, and whether controls select individual axis gradients or combine them remain design decisions for later.

- [ ] **Extend mathematical functions in equation input.** ([#6](https://github.com/Warsinger/math-visualization/issues/6)) **Initial coverage implemented:** `ln(expression)`, `sin(expression)`, `cos(expression)`, and `tan(expression)`, including nested calls, radians for trig, real-domain/nonfinite handling, and parser/evaluation/plotting regression tests. **Further extensions: pending.** Decide the additional function list and its syntax during later implementation; include real-domain handling and appropriate tests for every added function.

- [ ] **Add 2D Cartesian plotting with explicit 2D/3D selection.** ([#7](https://github.com/Warsinger/math-visualization/issues/7)) **Status: pending.** User-observed, not reproduced: plotting bare `x^2` shows nothing; `x^2=y` produces a 3D result when a 2D parabola was intended. In 2D mode, interpret a single-variable expression such as `x^2` as `y=x^2`, and support explicit `y=x^2`, producing a planar parabola with an appropriate 2D view and controls. Define clear UX for choosing 2D versus 3D and explaining shorthand meaning; do not silently reinterpret all equations globally. Preserve 3D implicit behavior, where `y=x^2` is a parabolic cylinder independent of z. Add tests for shorthand, explicit equations, planar geometry, and retained 3D behavior when implementing.
